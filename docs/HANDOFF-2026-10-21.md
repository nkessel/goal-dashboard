## 2. How to work (the loop that has been working)

1. **Read new feedback.** Sign in on the live app, open `/journal` and look under the "App feedback" entries (newest first, each with a timestamp and context line). Do everything sent since the last push.
2. **Implement.** Check types with `npx tsc --noEmit -p .`, lint the files you touched with `npx eslint <files>`, then run `npx next build --webpack`.
   - Some server pages already have `Date.now()` lint errors (e.g. `insights/page.tsx`, `friends/[id]/page.tsx`, `matrix/page.tsx`, `page.tsx`). Those are expected; only keep the files you touched clean.
3. **Look at it.** Run the dev server without a real database:
   ```
   NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:9 SUPABASE_SERVICE_ROLE_KEY=x AUTH_SECRET=devsecretdevsecretdevsecret npx next dev --webpack -p 3100
   ```
   Then screenshot with Playwright (`scripts/shot.mjs`, see below). Server actions fail offline ("Not signed in", HTTP 500 errors). That's expected; check layout and interactions only.
   - **`src/app/dev-preview/` is git-ignored, so it isn't in the repo.** It held small client-only harness pages: `/dev-preview`, `/today`, `/editor` (`?create`), `/map?s=…`, `/dock`, `/sent`, `/calendar` and more. Each renders real components with fake data. Recreate the ones you need (e.g. a page rendering `<TodayTaskBoard>` / `<DailyHabits>` / `<XpSummary bossesEnabled boss={…}>` with mock props).
4. **Ship.** Commit to `main` and push. Wait for the deploy:
   `gh api repos/nkessel/goal-dashboard/commits/<sha>/statuses --jq '.[0].state'`
   It can stay null for ~10 minutes before showing `success`.
5. **Verify live** in a browser (signed in as Nathan).
6. **Sync the laptop** (see below), then tell Nathan in a few lines what changed.

### Running SQL on production (Nathan approved this)

Use the Supabase dashboard SQL editor in a browser:
`https://supabase.com/dashboard/project/xjokponibpzyzbmypgyb/sql/new`

1. Set the query with `window.monaco.editor.getEditors()[0].getModel().setValue(sql)`.
2. Click the button whose text starts with "Run". For a destructive query, also click "Run query".
3. Read results via `document.querySelector('.rdg').textContent`. (`innerText` is empty when the pane is hidden.)

Tips and rules:
- Use `concat()` rather than `||`, because a NULL blanks the whole string.
- Verify every change with a separate SELECT.
- **Never use "Run without RLS".**
- Save each change as a migration file in the repo too.

## 4. Style and product taste (what he has asked for repeatedly)

- **Theme.** It's an RPG / storybook look: parchment, gold, dark forest green, `font-display` serif headings.
  - It must not feel like Windows: no separate grey title bars, no grip dots.
  - Use the CSS variables `--t-ink`, `--t-ink-soft`, `--t-gold`, `--t-panel`, `--t-xp`, etc. The app has 8 colour palettes (`src/lib/palettes.ts`).
  - The custom cursor set covers text, grab and resize too. New interactive elements should get the right cursor.
- **Fine settings fold away.** Advanced options sit behind a small caret link, closed by default ("like most fine settings should").
- **Settings live next to the thing.** e.g. a cog beside the Daily Habits header, a gear in the toucan's chat.
- **Motivating, never shaming.** No "0/3" counters; celebrate arriving. Effects all live in Settings: style, speed (`pace`), and how long the "Feedback submitted" card stays.
- **Menus.**
  - Every card's ⋯ menu also opens on right-click. A global `ContextMenuBridge` does this for any card with one ⋯ button.
  - Menus close on any outside click except on the feedback box (`[data-feedback-root]`).
  - Menus sit as low as fits and may cover the nav bar.
- **Editors.**
  - The quest editor autosaves when editing. When creating, closing asks Keep editing / Discard / Save as draft.
  - Ctrl/⌘+Enter and Ctrl/⌘+S save.
  - There's a × at the top right.
- **The Great Toucan Spirit** (`components/toucan/`, `layout/PerchedOwl.tsx`) is a wise, compassionate guide.
  - **Never** call it a "coach" or use clinical terms ("executive function").
  - It has three modes: simple, lite and full.
  - Nathan curates its lines in Settings.
  - "Talk with me" is a secret glint on its speech bubble.
- **Lint quirks (React compiler).**
  - No `Date.now()` / `Math.random()` in render. Use `freshKey()` in `lib/quest-drafts.ts`, or do it in handlers.
  - No components defined inside components.
  - `setState` inside an effect needs an eslint-disable with a reason.
  - Don't put Tailwind `translate-*` classes on elements whose keyframes animate `transform`.

## 5. What shipped today (all live)

- **Quest sequences** (`lib/data/sequences.ts`, `components/tasks/Sequence.tsx`).
  - Uses `tasks.locked_by_task_id` (B waits for A when `B.locked_by_task_id = A`), the same link rewards already use.
  - List functions run through `decorate()` in `lib/data/tasks.ts`. It hides waiting quests and gives the front quest `behind[]`.
  - Waiting quests show as stacked outlines with a "N after this" peek.
  - Finishing the front quest releases the next one into its spot on Today (`releaseNext` in actions.ts).
  - The quest menu has "Join a sequence…" and "Add a follow-up quest". The quest creator has a folded "Sequence" section.
- **Sub-habits** (migration 0065: `rites.steps` jsonb plus the `rite_step_checks` table).
  - Habits get a "0/4 ›" caret that opens round checkboxes. The last tick completes the habit.
  - The habit menu (and right-click) has "Add a sub-habit".
- **Daily Habits section.**
  - Closed by default.
  - A cog chooses the header style: Beads, Next up, Wins, Rising glow, or Just the title (localStorage `habits-header-look`).
- **Habit editor order:** Repeats (folded but open), Takes, Coins, XP, Due by (folded), then Sub-habits. The moon icon was replaced by the habit mark.
- **Feedback card** has a × to close it early. How long it stays is set in Settings → Sending feedback (`feedbackHold`).
- **Quest editor.**
  - The progress row is styled like the XP row.
  - Ctrl+S saves.
  - Each step's share of the quest is a slider.
  - The step state reads "Failed" (was "Didn't happen").
  - A small "paint…" box under the portrait sets the image prompt.
- **"Waiting for a time"** is off Today. It's still on the calendar and with the toucan.
- **Final Boss** (`components/xp/BossLine.tsx`, CSS `.final-boss-*`, `.fbp-*`).
  - The level badge's hover card is opaque royal purple and gold.
  - Clicking opens a portal panel (about ⅓ of the screen) announcing the Final Boss level. Enter leads to the level screen: progress bar, "Land the blows" (sessions linked to quests), and "How to beat it" (a battle plan saved in `bossPlans`, plus "Plan it with the Great Toucan Spirit").
  - This builds on the existing per-level bosses (`level_bosses` table, levels 1–9).
- **Toucan.**
  - Wisdom flourish choice: Glow (default), Bow, Flutter, Float, Leap or Still (`lib/toucan-flourish.ts`, gear in the chat).
  - Sayings are italic again.
- **Backpack items** show as circles outside the inventory pockets.
